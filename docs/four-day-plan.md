# Four-day delivery plan
The date of completion depends on when the four-day window starts. This schedule uses Day 1–4 instead of inventing an exact promised launch time.
Plan for approximately 6–8 focused hours per day, with scope kept to the defined India release. This is an estimate; measure actual progress after Day 1.

| Day | Antigravity work | Codex review | End-of-day evidence |
| --- | --- | --- | --- |
| 1 | Scaffold; brand tokens; responsive India homepage; logo and image integration | Review hierarchy, brand fidelity and mobile screenshots | Working desktop/mobile homepage |
| 2 | Services overview and one reusable service-detail template; six service records; fleet, about and contact pages | Focused review only if structure or content needs correction | All release routes navigable |
| 3 | Motion polish; WhatsApp enquiry draft; phone links; validation and accessible UI; metadata | Review enquiry behaviour and concrete bugs | Complete enquiry flow and responsive site |
| 4 | Real-device checks; image optimisation; copy/link review; build; preview/production configuration; fixes | Final blocker review | Deployable release and tested preview |

Use Days 1–3 for implementation and protect Day 4 for finishing. At the end of Day 1, stop changing the broad design direction unless there is a concrete serious problem.

If time is lost, retain the polished homepage, full services overview, fleet, about and contact routes. Add service-detail routes from the shared template as time permits; remove any unimplemented links. Keep the complete enquiry journey.
Country selection and UAE are already deferred, so they must not take time from India.

## Launch checks
- Current logo, new tagline and sampled colours.
- No unsupported stats or invented testimonials.
- Primary India cities shown as Hyderabad/Bengaluru/Pune.
- Brochure expansion cities are not labelled offices.
- All links resolve; browser back/forward work.
- Phone and WhatsApp buttons use the supplied numbers.
- WhatsApp opening is labelled correctly and never reports a booking confirmation.
- Draft email/domain values are not presented as active.
- Images load responsively and have meaningful alt text.
- Keyboard menu, focus visibility and reduced motion work.
- Production build succeeds without unresolved console errors.
- Set canonical URL and sitemap from the actual deployed production URL; omit fabricated domains.
- Keep a last-known-good commit for rollback.

A preview address is sufficient for a four-day demonstration if the domain is still unpurchased. Domain/email activation is separate from completing the site.
